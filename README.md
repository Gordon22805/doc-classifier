# OCR и Классификация Документов

Сервис принимает PDF, сканы и архивы, извлекает текст, определяет тип документа и раскладывает результат по папкам в ZIP.

Распознавание сканов идёт через vision-модель (любой OpenAI-совместимый API), классификация на объяснимых правилах, без «чёрного ящика»: для каждой страницы видно, какое правило сработало и с каким отрывом от второго кандидата.


## Что показывает проект

- **Конвейер обработки документов**: маршрутизация «текстовый слой или OCR», каскад из четырёх стратегий распознавания, нормализация, классификация, сборка архива.
- **Объяснимая классификация**: 14 типов документов, приоритет правил, взвешенный скоринг признаков, контекст многостраничных файлов. Неуверенный результат честно уходит в `unknown`, а не угадывается.
- **Работа с вложениями**: ZIP и 7Z, вложенные архивы, защита от Zip Slip и архивных бомб.
- **Честные ошибки**: если распознать страницу нечем, страница получает статус ошибки с причиной, а не пустой «успех».
- **Тесты и самопроверка**: 54 unit-теста плюс `selftest.py`, который поднимает настоящий сервер и прогоняет 56 сценариев по HTTP.

## Быстрый старт

```bash
pip install -r requirements.txt
copy .env.example .env        # Linux/macOS: cp .env.example .env
py -m uvicorn backend.main:app --port 8000
```

Откройте http://127.0.0.1:8000, интерфейс загрузится сразу.

Без ключа сервис работает в ограниченном режиме: PDF с текстовым слоем и DOCX обрабатываются полностью, сканы и изображения получают понятную ошибку. Для распознавания сканов вставьте ключ в `.env`:

```env
OPENAI_API_KEY=sk-or-v1-...
VISION_MODEL=qwen/qwen2.5-vl-72b-instruct:free
VISION_BASE_URL=https://openrouter.ai/api/v1
```

Ключ OpenRouter выдаётся бесплатно: https://openrouter.ai/keys. Подойдёт любой OpenAI-совместимый провайдер, таблица альтернатив ниже.

## Как проверялось

```bash
py -m pytest          # 54 unit-теста
py selftest.py        # 56 проверок по HTTP без ключа
py selftest.py --mock # 55 проверок со сканами через локальную заглушку провайдера
```

`selftest.py` поднимает реальный процесс uvicorn и прогоняет файлы через HTTP: PDF с текстовым слоем, DOCX, многостраничный PDF с разными типами, ZIP, Zip Slip, ручную коррекцию, пересборку, скачивание архива, битые файлы. С флагом `--mock` дополнительно проверяется распознавание сканов на локальной заглушке OpenAI-совместимого API, без сети и без ключа.

Реальное распознавание через облачную модель в CI не проверяется: нужен ключ.

## Возможности

- **Поддержка форматов**: PDF, JPG, PNG, HEIC, DOCX, ZIP, 7Z
- **OCR через vision-модель**: любой OpenAI-совместимый провайдер (по умолчанию OpenRouter)
- **Маршрутизация по качеству**: автоматическое определение необходимости OCR
- **Каскадный OCR**: несколько стратегий распознавания (original, focused, enhanced, tiled)
- **Объяснимая классификация**: правила, регулярные выражения, взвешенный скоринг, n-граммы
- **Типы документов**: паспорт, ЕГРН, ДКП, ПДКП, ДДУ, ЗАГС, наследство, ЕЖД, НДФЛ, СФР, платёжные поручения, бухгалтерская отчётность, справки
- **Контекстная классификация**: учёт многостраничных документов
- **Ручная коррекция**: веб-интерфейс для проверки и исправления результатов
- **Безопасность**: защита от Zip Slip, ограничения на размеры и количество файлов
- **Приватность**: диагностика без персональных данных

| `MAX_FILE_SIZE_MB` | Макс. размер файла | 100 |

### Профили OCR

Профиль задаёт промпт к vision-модели:

- **original**: базовый промпт, сохранить структуру документа
- **focused**: акцент на мелком тексте и деталях (изображение обрезается по содержимому)
- **enhanced**: максимум точности для низкокачественных сканов (контраст + резкость)
- **tile**: распознавание фрагментов с перекрытием 18%

## Классификация

### Поддерживаемые типы

- **passport**: Паспорт РФ
- **egrn**: Выписка ЕГРН
- **dkp**: Договор купли-продажи
- **pdkp**: Предварительный договор купли-продажи
- **ddu**: Договор долевого участия
- **zags**: Документы ЗАГС
- **inheritance**: Документы о наследстве
- **ezd**: Единый жилищный документ
- **ndfl**: Справки 2-НДФЛ
- **sfr**: Документы СФР
- **payment_order**: Платёжные поручения
- **accounting**: Бухгалтерская отчётность
- **reference**: Справки
- **unknown**: Не распознан

### Логика классификации

1. Роль из имени файла + подтверждение в тексте
2. Структурные признаки ЕГРН (минимум 3 независимые группы)
3. Точный специфичный заголовок
4. Нечёткое совпадение токенов заголовка
5. Паспортные признаки (комбинация серии, кода, дат, MRZ)
6. Контекстные правила
7. Номер формы + обязательная фраза
8. Взвешенный скоринг признаков
9. N-граммы (если обучена модель)

Результат: **unknown**, если score < 2.0 или margin < 2.0

## Ограничения и внешние зависимости

### Нужна vision-модель (любой OpenAI-совместимый провайдер)

Приложение не включает собственный OCR движок. Для распознавания сканов используется vision-модель через OpenAI-совместимый API. Провайдер задаётся парой `VISION_BASE_URL` + `VISION_MODEL`.

**Текущая настройка проекта: OpenRouter (нужен ключ)**
```env
OPENAI_API_KEY=sk-or-v1-...
VISION_MODEL=qwen/qwen2.5-vl-72b-instruct:free
VISION_BASE_URL=https://openrouter.ai/api/v1
```

Ключ выдаётся бесплатно: https://openrouter.ai/keys, модель с суффиксом `:free` работает без оплаты.

Без ключа сервис запускается и работает, но распознаёт только документы с текстовым слоем (PDF с текстом, DOCX). Сканы и изображения получают статус ошибки с пояснением причины: молча пустого результата не будет.

**Другие провайдеры (любой OpenAI-совместимый API):**

| Провайдер | `VISION_BASE_URL` | `VISION_MODEL` |
|---|---|---|
| OpenRouter | `https://openrouter.ai/api/v1` | `qwen/qwen2.5-vl-72b-instruct:free` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/` | `gemini-2.5-flash` |
| OpenAI | *(пусто)* | `gpt-4o` |
| Локальная модель (Ollama / LM Studio) | `http://127.0.0.1:11434/v1` | `qwen2.5vl:3b` |

Для локального сервера ключ не нужен: клиент подставляет заглушку только для адресов `localhost` / `127.0.0.1`. Для облачных провайдеров ключ обязателен, иначе OCR отключается, а не уходит в сеть с фиктивным ключом.

> **Для пользователей из РФ:** `api.openai.com`, `openrouter.ai`, `api.groq.com`, `api.together.xyz` отвечают `403 Forbidden` без VPN. Google Gemini, `vsegpt.ru`, `proxyapi.ru`, `polza.ai` доступны напрямую.

Быстрая проверка провайдера одним запросом, без запуска сервера:
```powershell
py check_ocr.py
```

**Как это работает:**

1. Страница рендерится в JPEG (220 DPI, макс. сторона 3200 px, качество 95).
2. Изображение отправляется в Chat Completions как base64 data-URI с `detail: "high"`, `temperature: 0`.
3. Модель возвращает текст; профиль (`original` / `focused` / `enhanced` / `tile`) задаёт промпт, а не параметры движка.
4. Сетевые ошибки, таймауты, 429 и 5xx повторяются с экспоненциальной задержкой; прочие ошибки (например, невалидный ключ) не повторяются.

Если OCR недоступен:
- Приложение продолжит работать
- PDF с текстовым слоем обрабатываются
- Сканы будут помечены как ошибка обработки
- Веб-интерфейс покажет статус ошибки для соответствующих страниц

Текущий провайдер виден в `GET /api/health` (`vision_model`, `vision_base_url`).

### Метрики качества

Готового скрипта для расчёта Accuracy / Precision / Recall по эталонной разметке в проекте нет, поэтому конкретные цифры качества здесь не заявляются: они зависят от выборки документов и доступной vision-модели.

Чтобы измерить качество на своих данных, нужны размеченные файлы и модуль оценки, но в этой версии его нет.

### Что не реализовано

- **Обучение n-gram модели**: метод `classifier.train_ngrams()` есть, но требует размеченных данных
- **Оценка метрик**: нет скрипта для расчёта Accuracy, Precision, Recall
- **Визуальные признаки**: анализ изображения (например, цветовые метки на бланке) не используется, классификация идёт только по тексту

## Безопасность

- **Zip Slip**: проверка путей при распаковке архивов
- **Архивные бомбы**: лимиты на количество файлов и общий размер
- **Path Traversal**: валидация имён файлов
- **Персональные данные**: не логируются в диагностику
- **DoS**: ограничение параллельности OCR, размеров файлов

## Диагностика

Для каждой страницы сохраняется:
- source_file, page_number
- text_source (text_layer, llm_ocr, focused, enhanced, tiled, docx)
- текстовая длина
- количество и виды OCR попыток
- результат проверки качества
- classification_score, margin
- сработавшее правило
- processing_time_ms
- error (при наличии)

**Не сохраняются**: текст страницы, ФИО, даты рождения, адреса, номера документов, фотографии.
